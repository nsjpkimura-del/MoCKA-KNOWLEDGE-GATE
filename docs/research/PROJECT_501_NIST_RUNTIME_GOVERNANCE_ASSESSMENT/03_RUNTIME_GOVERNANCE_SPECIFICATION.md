# 03 — Runtime Governance Specification

This file describes what MoCKA is, as documented and as evidenced in its public core repository. Written for a reader with no prior MoCKA context.

## 1. Institutional model — [Layer 1 / Layer 3]

MoCKA describes itself (public README, `m-sirius-k/MoCKA` — **Layer 1, Verified Public Evidence**) as a "deterministic governance architecture" implementing a closed operational loop: **Observation → Record → Incident → Recurrence → Prevention → Decision → Action → Audit** (`mocka_Movement`), with a parallel degraded-mode path (`shadow_Movement`) intended to preserve partial function during component failure.

Constitutional principles stated in the public repository include that the Event Ledger is append-only, that decisions preserve "5W1H" (who/what/when/where/why/how) context, and that the Event Ledger is treated as the single source of truth over any derived summary or cache. The general principle is stated in the public `MoCKA` repository's `docs/CONSTITUTION.md` (**Layer 1**). **Independent Audit correction (2026-07-11):** the citation originally read simply "`CONSTITUTION.md`" without the `docs/` prefix. This is ambiguous and, read as the root-level file, wrong: `origin/main:CONSTITUTION.md` (5 lines) is an unrelated UTF-8 encoding policy document containing none of the "5W1H"/append-only language. The substantive claim itself is verified accurate — `origin/main:docs/CONSTITUTION.md` (25 lines) does state "Event ledger is append-only" and "All decisions preserve 5W1H" verbatim — but the original citation pointed to the wrong file path. Corrected here. The exact wording quoted in earlier drafts of this project was attributed to `MOCKA_OVERVIEW.json` and marked Layer 2 (internal-only) — **this was a classification error, corrected in this revision**: `data/MOCKA_OVERVIEW.json` is a tracked file on `origin/main` (last modified 2026-07-08, commit `b7439e26d`) and is therefore **Layer 1, Verified Public Evidence**. See §4 below for the full correction and a directly related finding this correction surfaced.

## 2. Core governance mechanisms — [Layer 1, Verified Public Evidence]

Confirmed present in the public `MoCKA` repository at `origin/main` @ `e7a779a4cc982e75064249bdbcd9e3f2f1d907d1` (2026-07-10), the last public commit at the time of this assessment.

- **Decision Layer** (`decision/decision_engine.py`, `decision/decision_model.py`, `decision/decision_registry.py`, `decision/risk_analyzer.py`, `decision/priority_scorer.py`): explicitly documented as non-executing — code and accompanying documentation state the Decision Layer performs no destructive actions; final authority is deferred to a separate "Governance Layer (GL1–GL7)."
- **Human Gate mechanism** (`governance/human_gate_continuity.py`, tested by `tests/test_human_gate_continuity.py`): a human-approval component present and covered by tests in the public repository.
- **Audit / cryptographic sealing** (`audit/system_audit.py`, `audit/drift_report.py`, `audit/ed25519/key_manager.py`, `audit/ed25519/daily_signature.py`, `audit/ed25519/governance_chain_verify.py`, `verify_all.py`, `verify_full_chain_and_signature.py`, `self_audit/audit_engine.py`): an Ed25519-based signature chain with dedicated verification entry points.
- **Drift detection** (`audit/drift_report.py`; `core_kernel/governance/intelligence/drift_interpreter.py`; `core_kernel/governance/self_verification/traceability/drift_detection.py`): code with an explicit design distinction, stated in its own docstring, between "Implementation drift" and "Evidence/Audit drift," and an explicit statement that the module "never recomputes a Decision or rewrites a record — it only flags mismatches."
- **Role policy** (`governance/keys/role_policy.json`, `governance/verify_role_policy.py`): a versioned schema (`mocka.keys.role.definition.v1`) with accompanying verification code.
- **Multi-agent orchestration ("Orchestra")** — substantially larger public footprint than initially surveyed; corrected in this revision after a targeted keyword pass (`appendix/REVIEW_LOG.md`). Confirmed tracked on `origin/main`: `core_kernel/orchestra/` (`orchestra_engine.py`, `event_bus.py`, `execution_graph.py`, `orchestrator_api.py`, `replay_engine.py`, `session_state.py`, `persistence/sqlite_store.py`, `persistence/schema.py`, `tests/test_orchestra_engine.py`), `core_kernel/orchestra_core/` (`orchestra.py`, `models.py`, `tests/test_orchestra.py`), `orchestra/conflict_interpreter.py`, `interface/orchestra_spec.md`, ten iterative `tools/mocka_orchestra_v01.py`–`v10.py` scripts plus `tools/mocka_orchestra_parallel_v01.py`–`v06.py`, `tools/orchestra_context_bridge.py`, `caliber/orchestra/mocka_orchestra_v10.py`, and the multi-agent gateway itself: `gateway/gateway.py`, `gateway/adapter_gpt.py`, `gateway/openapi.yaml`. This is real, tested code with a persistence layer and a replay engine, not documentation-only. It substantially upgrades the "Multi-Agent Coordination" comparative-matrix row (`05_COMPARATIVE_ANALYSIS.md`) from what an earlier draft of this project stated.
- **Testing and CI**: 95 files under `tests/` directories repository-wide; six active GitHub Actions workflows (`canary_overrides.yml`, `mocka_guard.yml`, `mocka_regression.yml`, `phase18_determinism_matrix.yml`, `phios_regression.yml`, `transparency.yml`). **Independent Audit correction (2026-07-11):** `git ls-tree -r origin/main -- .github/workflows/` shows **seven** tracked workflow files, not six — `research-gate-demo.yml` also exists at `origin/main` and was omitted from this count throughout the project (it is correctly listed for `mocka-public`, which also carries a copy). This does not change the "Verified Public Evidence" status for R6/TEVV, but the workflow count should read seven wherever six is stated (this file, `appendix/evidence/full_repository_survey.md`, `appendix/evidence/repository_evidence_register.md`).

## 3. Broader repository constellation — [Layer 1 / Layer 3, mostly documentation]

Seven additional public repositories describe extensions of the same architecture but, per `appendix/evidence/`, contain little to no corresponding implementation:

- `mocka-runtime` — "Five Engine Architecture" (Runtime, Observatory, Knowledge Core, Storage, Audit), "Single Entry Point" execution guarantee. **[Layer 3 only]** — zero source-code files.
- `mocka-outfield` — infield/outfield separation boundary, public event ledger. **[Layer 3 only]**; the tracked "public ledger" (`ledger/events_public.json`) is an empty array.
- `mocka-public` — published technical notes (PDF) and verification/seal declarations. **[Layer 1 for the papers themselves; Layer 3 for the architecture claims]**; the README's instructed verification script (`verify_chain.py`) does not exist.
- `mocka-civilization` — 21-phase design/doctrine repository (146 files, 139 Markdown), six "Immutable Principles" (Transparency, Reproducibility, Accountability, Immutability, Neutrality, Continuity). **[Layer 3 only]** — no code.
- `mocka-external-brain` — multi-agent "share → ask → reply → decide" deliberation protocol across four AI systems. **[Layer 1, Partially Implemented — corrected by Independent Audit, 2026-07-11, see `appendix/INDEPENDENT_AUDIT_REPORT.md` Finding 1]**: `logs/bus/events.csv` (3,835 bytes) and `logs/bus/rounds/round_2026-02-08-00{1,2}.md` are tracked on `origin/main` and contain real, timestamped deliberation records (Feb 2026) using exactly the schema described in the README prose (`event_id`, `round_id`, `motion`, `actor`, `parent_event_id`, `evidence_ref`, `hash` columns). This is real data demonstrating the protocol was actually exercised, not merely documentation. The README's own Quick Start reference to `logs\bus\events.csv` is therefore accurate — that file **does** exist, contrary to what this project's v1.0 draft and `appendix/evidence/full_repository_survey.md` originally stated.
- `mocka-transparency` — most code-bearing of this group: real Ed25519 signing/verification/RFC3161-timestamping scripts and sample data exist. **[Layer 1, Implementation In Progress]** — but the README's advertised single-command verifiers (`verify_chain.py`, `verify_all.py`) do not exist; actual entry points are per-sample scripts.
- `MoCKA-KNOWLEDGE-GATE` (this repository) — real server/middleware/integration code alongside extensive narrative "PHASE_N_COMPLETE" documents. **[Layer 1, Implementation In Progress]** — 13 CI workflow files exist but are all under `.github/workflows.disabled/`; "PHASE_COMPLETE" documents are self-attested narrative claims, not evidence independently verifiable via a passing CI run in this repository.

Full per-repository detail is in `appendix/evidence/`.

## 4. Living Context, TODO Register, and Event storage — mixed Layer 1 / Layer 2 (corrected in this revision)

A Phase 1 re-investigation (`appendix/REVIEW_LOG.md`) found that several artifacts this project's v1.0 draft classified as Layer 2 (Internal, Not Publicly Verifiable) are in fact tracked on `origin/main` and are therefore **Layer 1, Verified Public Evidence**:

- `data/MOCKA_OVERVIEW.json` ("Living Context" master file) — tracked, last modified 2026-07-08 (commit `b7439e26d`).
- `data/MOCKA_TODO_ACTIVE.json`, `data/MOCKA_TODO.json`, `data/MOCKA_TODO_ARCHIVE.json`, `data/MOCKA_TODO_REFERENCE_LOCKED.json` (TODO Register) — tracked, `MOCKA_TODO_ACTIVE.json` last modified 2026-07-10 (commit `3755c107f`), one day before this project's evidence-gathering date.
- `data/lever_essence.json`, `data/events_latest.json`, `data/MOCKA_ENDPOINTS.json`, `data/essence_condensed.json`, `data/ping_latest.json` — tracked.
- A **small, dated sample of raw Event Ledger records**: 27 files under `data/storage/infield/` and further files under `data/storage/outbox/PILS_DONE/`, all timestamped 2026-04-01 through 2026-04-04. This is genuine Layer 1 evidence that the Event Ledger's record format is real and public, but it is a stale historical snapshot, not the live ledger (which, per Layer 2 records, held 15,402 events as of 2026-07-11).
- The tracked root-level `mocka_events.db` on `origin/main` is **not** the live database — cross-referenced against internal Integrity record `IC_20260705_013` (Layer 2), which independently confirmed this exact file is a 0-byte residue/ghost file, not live data. The actual live event database is not tracked in the repository.

**A directly related finding surfaced by this correction:** `data/MOCKA_OVERVIEW.json`, as read from `origin/main`, contains the field `"classification": "PRIVATE - ローカルのみ管理"` ("PRIVATE — local management only") in its own metadata block — yet the file itself is committed to a public GitHub repository. This is a genuine, previously undocumented self-classification inconsistency in MoCKA's own practice, not a criticism from this project's authors; it is disclosed here per the no-advocacy/full-disclosure principle (`00_PROJECT_CHARTER.md`). See `07_GAP_ANALYSIS.md` §6 for its Gap Analysis treatment.
