# 01 — Executive Summary

MoCKA ("Model of Cybernetic Knowledge Architecture") is a personal/independent research project developing a governed, event-sourced runtime for AI-assisted work, built around an append-only Event Ledger, a Decision Ledger, a multi-stage Human Gate approval mechanism, cryptographic audit sealing, and a self-reported Integrity Classification system that logs the project's own governance failures as first-class records.

The NIST AI RMF Profile on Trustworthy AI in Critical Infrastructure is, as of this writing, at the **Concept Note stage** (published 2026-04-07). No formally published NIST discussion draft was independently locatable during this assessment (see `02_NIST_REQUIREMENT_ANALYSIS.md` §1 for the full evidentiary discussion of this gap). Consequently, this project compares MoCKA against the **themes and trustworthiness characteristics explicitly stated in the Concept Note and the underlying NIST AI RMF 1.0**, rather than against a requirement-numbered draft profile, which does not yet exist in verifiable public form.

Within that constraint, the assessment finds:

- MoCKA's **core repository** (`MoCKA`, public) contains a substantial, tested, and cross-referenced implementation of several governance mechanisms directly relevant to NIST's themes: a non-executing Decision Layer subordinate to a human-approval gate, an Ed25519 cryptographic audit/signature chain, drift-detection code that explicitly separates "implementation drift" from "evidence/audit drift," and a role-policy schema with verification code. **[Layer 1 — Verified Public Evidence]**
- Seven of the eight other public MoCKA-family repositories surveyed are **predominantly documentation**, describing architectures, protocols, and verification procedures that do not have corresponding code in those repositories. In three cases, a repository's own README "Quick Start" instructions reference scripts that do not exist in the tracked repository. **[Layer 1 — Verified Public Evidence of a documentation/implementation gap, not a defect assessment of the underlying design]**
- Internally, MoCKA maintains an active, dated Decision Ledger (56 records) and Integrity Classification Ledger (31 records) that show a working, self-critical governance process — including at least one **currently Open, unresolved internal finding (IC_20260708_004)** describing a live execution path that can trigger an audit-seal action after only an automated policy check, without a verified separate human-approval step. **[Layer 2 — Internal Evidence, Not Publicly Verifiable]**
- MoCKA's internal governance process contains **repeated, explicit decisions rejecting autonomous self-approval loops** (e.g., DC_20260708_001, DC_20260708_005, DC_20260708_008, DC_20260706_001) — a recurring, self-imposed constraint that maps closely to the NIST Concept Note's "human-in-the-loop oversight" language, but this pattern is currently visible only in internal records, not in public repository evidence. **[Layer 2 — Internal Evidence, Not Publicly Verifiable]**

The overall picture is of a project with **real, tested governance code in its core repository (Layer 1)**, a broader public "constellation" of repositories that mostly documents intent rather than demonstrating it (Layer 1 / Layer 3), and an internal operational discipline that is more mature than what is externally visible (Layer 2). `07_GAP_ANALYSIS.md` treats this visibility gap as a first-class finding in its own right.

**Revision note (R01 Phase 1 review, 2026-07-11):** a targeted re-investigation triggered by R01's review requirement to explicitly catalogue Living Context, Orchestra, and Event Ledger found that this project's own v1.0 draft had *understated* MoCKA's public evidence in two material ways — Orchestra (multi-agent coordination) has substantial real, tested implementation in the core repository that was originally missed, and the Living Context file (`MOCKA_OVERVIEW.json`) and TODO Register are tracked on `origin/main` and are therefore Layer 1 (Public), not Layer 2 (Internal) as originally stated. The same re-investigation also surfaced a genuine discrepancy worth independent note: `MOCKA_OVERVIEW.json` is public on GitHub despite an internal metadata field in the file itself declaring it `"PRIVATE"`. All three points are corrected throughout this project and logged in full in `appendix/REVIEW_LOG.md`.
